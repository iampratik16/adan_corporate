# Adan Corporate

The website for Adan Corporate, an international corporate advisory firm.

Next.js 16 (App Router), TypeScript in strict mode, Tailwind CSS 4, pnpm. Static by default;
every route prerenders.

---

## Running it

```bash
pnpm install
pnpm dev                      # http://localhost:3000
```

Node 20.9 or newer. `pnpm` is the package manager; the lockfile is committed.

```bash
pnpm build && pnpm start      # production build, served locally
pnpm check                    # typecheck, lint, format, Playwright, axe
```

### The checks worth knowing about

```bash
npx tsx scripts/check-contrast.ts        # WCAG audit of every token pair
npx tsx scripts/check-media-contrast.ts  # text over photography, glyph-mask method
npx tsx scripts/screenshot.ts            # every route at 390/768/1440/1920 into .review/
npx tsx scripts/screenshot.ts / --width 390 --full
```

`check-media-contrast.ts` is the unusual one. Text over a photograph cannot be audited from tokens,
so it screenshots the page twice, once with the text visible and once hidden, diffs the two to
derive a mask of the actual letterforms, and tests the computed text colour against the background
at exactly those pixels, across the poster and every extracted film frame. It needs the production
server running on port 3111.

## Environment

Copy `.env.example` to `.env.local`. Nothing is required to run the site.

| Variable               | Required                 | What it does                                                                                                                                             |
| ---------------------- | ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `RESEND_API_KEY`       | No                       | Sends the contact form. **Without it the form still works**: the payload is logged and the success state shows, so the flow is testable with no secrets. |
| `CONTACT_TO_EMAIL`     | No                       | Where enquiries go. Defaults to the `partners@` mailbox.                                                                                                 |
| `GOOGLE_CLOUD_PROJECT` | Only to regenerate media | The Vertex AI project.                                                                                                                                   |

There are no API keys in this repository and none are needed to build it. Media generation uses
Application Default Credentials.

## How it is put together

```
content/          Typed, Zod-validated content. The single source of fact.
  schema.ts       The contract. A malformed record fails the build.
  people.ts       32 people, biographies carried from the old site and cleaned
  transactions.ts 36 completed transactions and 31 current mandates
  pillars.ts      The five service pillars, their capabilities and sequences
  offices.ts      14 offices, plus the cities where partners sit
  figures.ts      Every published number, each with provenance and a confirmation flag
  site.ts         Identity, navigation, mailboxes, the contact router
  media.ts        Generated by the media pipeline. Do not edit.
  portraits.ts    Generated by the portrait pipeline. Do not edit.
  redirects.ts    Every old URL mapped to its new home
  _source/        Cleaned abstracts of the old site. The evidence behind every fact.

src/
  app/            Routes. Server components unless interactivity demands otherwise.
  components/     layout/ ui/ shared/ home/ and one folder per route group
  lib/            fonts, time formatting

scripts/
  media/          shots.ts generate.ts process.ts portraits.ts manifest.json
  check-contrast.ts  check-media-contrast.ts  screenshot.ts

docs/             BRIEF, DECISIONS, CLIENT-QUESTIONS, COPY-DRAFT, design-direction
```

A headless CMS can replace the files under `content/` without touching a component, provided it
satisfies `content/schema.ts`.

**`CLAUDE.md` is the working brief for anyone, human or otherwise, editing this codebase.** Read it
before changing anything: it carries the token rules, the motion rules, the truth rules and the
performance budgets.

## Regenerating the media

Every photograph and film on this site is generated through **Vertex AI using Application Default
Credentials**. No API key is ever used or stored.

```bash
gcloud auth application-default login
export GOOGLE_CLOUD_PROJECT=$(gcloud config get-value project)

pnpm media:generate                  # stills and short films for the pages
pnpm media:generate hero-still       # one shot by id
pnpm media:process                   # grade, encode, write content/media.ts
npx tsx scripts/media/portraits.ts   # the real headshots (no model involved)
```

The 60-second hero film has its own pipeline, described in `docs/HERO-FILM.md`:

```bash
npx tsx scripts/media/generate-hero.ts --stills        # the 7 anchor stills
npx tsx scripts/media/generate-hero.ts --draft         # all 8 shots, fast tier
npx tsx scripts/media/generate-hero.ts --final 1 4 6 8 # approved shots, standard tier
npx tsx scripts/media/assemble-hero.ts                 # grade, crossfade, encode, QC frames
```

Approve a take by copying it to its bare id, e.g.
`cp hero-05-window-take2.png hero-05-window.png`. The assembler reads the bare names, so an
unapproved shot can never reach the film.

`scripts/media/shots.ts` holds the shot list and every prompt, including the house look appended to
all of them. `scripts/media/manifest.json` records every call: model, prompt, parameters, timestamp
and whether the take was kept.

Originals land in `media/originals/` (git-ignored). Processed output goes to `public/media/`.

**Models, as probed on this project.** `gemini-3-pro-image` answers on `global` only;
`veo-3.1-generate-001` and `veo-3.1-fast-generate-001` answer on both `global` and `us-central1`.
Every flash image model and every Imagen endpoint returns 404. Google retires model IDs often: if
one is rejected, list what is available, pick the nearest equivalent, and record the swap in
`docs/DECISIONS.md`.

**Portraits are different and the rule is absolute: no generative model ever touches an image of a
named person.** `scripts/media/portraits.ts` downloads the existing headshots and processes them
deterministically. The source images are circular avatars with a red ring baked in, so it detects
the ring, crops the largest 4:5 rectangle that fits inside it, and matches every portrait to a
common tone. Output stops at 320px because that is what the source genuinely supports.

## Deploying

Built for Vercel. Push the repository, set the framework to Next.js, and add `RESEND_API_KEY` and
`CONTACT_TO_EMAIL` if the contact form should send mail.

`next.config.ts` carries the redirect map from `content/redirects.ts`, the security headers, and a
one-year immutable cache policy on `/media/*`. Generated media is committed so a deploy never needs
Vertex AI credentials.

Anywhere else that runs Node works too: `pnpm build && pnpm start`.

## The budgets this site is held to

|                     | Target                                                                         |
| ------------------- | ------------------------------------------------------------------------------ |
| LCP                 | under 2.0s on a mid-range phone on 4G, with the hero poster as the LCP element |
| CLS                 | under 0.05                                                                     |
| INP                 | under 200ms                                                                    |
| Homepage JavaScript | under about 170 kB gzipped on first load                                       |
| Lighthouse          | 95+ accessibility, best practices, SEO; 90+ mobile performance                 |
| Accessibility       | WCAG 2.2 AA                                                                    |
| Film                | at most 3 MB desktop, 1.5 MB mobile, audio stripped                            |

The hero poster is 13.9 kB at 960px in AVIF and the hero film is 0.52 MB at 1920px. See
`docs/FINAL-REPORT.md` for measured results.

## Before this goes live

Read **`docs/CLIENT-QUESTIONS.md`**. Four things block launch:

1. the regulatory and legal footer wording, which is currently a visible placeholder
2. whether nine people commented out of the old site are still with the firm
3. sign-off on the AI & Digital proposition
4. a vector logo

Every published figure on the old site contradicts another figure on the old site. Each one is
printed with a confirmation flag and its provenance, and the "as at" footnote is a visible
placeholder rather than an invented date.
